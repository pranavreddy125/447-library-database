# 447 Library Database

Term-project workspace for designing a library database product. The team is currently preparing **Project Part One: Vision and Plan**.

> Status: starter repository only. The team still needs to review the detailed project description and complete the marked fields in the planning documents.

## Repository contents

- [`PROJECT_PLAN.md`](PROJECT_PLAN.md) — outline for the vision, scope, and team organization deliverable
- [`MEETING_LOG.md`](MEETING_LOG.md) — reusable meeting record template

## Working agreement

1. Keep project artifacts in this repository so the team has one source of truth.
2. Create a short-lived branch for substantial changes; use clear commit messages and open a pull request for review.
3. For small, agreed-upon documentation corrections, direct commits to the default branch are acceptable if the team approves.
4. Do not commit passwords, credentials, private student records, or production data.
5. Record every team meeting in `MEETING_LOG.md`, including assignments, owners, and deadlines.
6. From the second meeting onward, review every prior assignment and record its completion status and comments.
